Three Implementation Approaches

All three cover the same four concerns: image fetching, pixel→ASCII conversion, terminal mouse events, and the overlay render mode.

A
jimp (pure-JS) + ANSI mouse events
Pros
  • jimp is pure JS — no native compilation, matches project philosophy
  • JPEG + PNG decoding built-in; resize to target cols × rows before converting
  • ANSI mouse protocol (\x1b[?1000h) is already supported by most terminals and slots cleanly next to the existing raw-mode input
  • ASCII palette + per-char ANSI 256 color from each pixel's RGB — one pass
Cons
  • jimp adds ~2 MB to node_modules
  • First conversion takes ~100–200 ms (acceptable; cached after that)
  • Mouse click coordinates are in character-cell units — requires mapping row/col back to the header region
Spotify API → album.images[0].url → axios fetch (buffer) → jimp.read() → resize to (W/2 × vizH) → pixel → ASCII + ANSI color → cache string[]
B
sharp (native) + ANSI mouse events
not recommended
Pros
  • sharp is extremely fast (libvips under the hood)
  • Sub-5ms resize + raw pixel buffer extraction
  • Best image quality at small sizes
Cons
  • Native module — requires node-gyp, platform-specific binaries
  • Directly contradicts the project's no-native-modules rule
  • Complicates CI, cross-platform builds, and fresh installs
Ruled out: native compilation breaks the project's core constraint. Listed for completeness.
C
jimp + ANSI mouse + plasma overlay reuse
★ recommended
What's different from A
  • Same jimp pipeline — but the plasma layer reuses the existing wavefield renderer running at reduced amplitude, not a separate noise generator
  • The expanded view is a new VisMode ("album-art") — engine's renderFrame() dispatches to it the same way it dispatches to spectrum/wavefield
  • Mini header icon is pre-converted to a fixed 4×2 char thumbnail once and stored alongside the full-size cache
  • Mouse click maps to the header region bounds from computeLayout() — reuses existing layout system
New modules
  • album/fetcher.ts — fetch image buffer from URL
  • album/converter.ts — jimp pixel→ASCII, outputs AsciiArt object (thumbnail + full)
  • album/cache.ts — keyed by track ID, LRU size 3
  • visualizer/modes/albumArt.ts — render the overlay mode
  • Extend ui/input.ts — add mouse event parsing alongside existing keypress handling
pollSpotify() gets imageUrl → cache miss? fetch + convert → store AsciiArt in cache → header icon written each frame → mouse click on header rows 0–1 → mode = "album-art"
Recommendation: Approach C. It extends the existing architecture cleanly — new render mode, new album module, minimal changes to the engine. The plasma background comes for free by running the wavefield renderer at low amplitude behind the overlay. No new architectural patterns needed.
